# Native analysis and business workflow

Use the selected domain guide for its methodology, formulas, output templates and
acceptance checklist. Produce the actual requested analysis or artifact using native
file, web, document and computation tools; do not stop at explaining the recipe.

The installed library is immutable. Business/author context belongs in the selected
workspace's `.codex-context/`, never in the pack, a public repository by default, or
a former author's home. Read user-supplied context first. If required context is
missing, use the public blank template under `library/templates/` as a questionnaire;
ask only the facts needed for the current decision. Do not invent revenue, budgets,
prices, customer names, author biography, product positioning or case results.

Distinguish planning from account operations. A media plan, campaign draft or CRM
design does not require authenticating every service named in an example. If actual
account data is necessary, discover a currently available connector and verify its
read scope. Request an export or the exact connection if absent, not arbitrary keys.
Do not launch ads, contact leads, edit campaigns, make payments or publish by inference.

Use current primary sources for external facts. Date the evidence, distinguish source
facts from estimates, retain units/currencies/cohort definitions, and calculate from
provided data. For research/competitive work, deliver links and uncertainty rather
than fabricated observations. Apply applicable legal/financial research boundaries.

For a council or multi-stage pipeline, perform the logical perspectives sequentially
unless delegation is explicitly authorized. If independent experts are necessary to
the requested result, disclose the absence of independent evaluation. Never fake
multiple agents, external model votes or independently verified findings.

Read back the resulting artifact, reconcile calculations and source claims, and
report unavailable data separately from completed analysis.

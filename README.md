# Codex Configuration Pack

Обезличенный, переносимый порт [Claude Code Configuration Pack](https://github.com/JHamidun/claude-code-config-pack).
Исходная ревизия: `e9f5f9e019d3c6dc9fe83b00499f223b5f9e6d32`.

**Статус: проверяемая базовая версия порта, а не обещание полной совместимости Claude runtime.**
Рабочие инструкции, поиск по каталогу, нативные TOML-профили агентов и установщик адаптированы.
Исходные скрипты, сторонние сервисы и хуки не объявляются рабочими после одной замены путей.

## Исполняемая адаптация — в работе

В локальной следующей версии появились три проверенных офлайн-помощника:
структурированный Git status, профилирование CSV и создание/восстановление снимков
артефактов. Поиск понимает их русские формулировки; `catalog.py --prepare <id>`
выдаёт Codex проверенную инструкцию с разрешёнными путями. Codex затем выполняет
действие, а не предлагает пользователю самостоятельно запускать команды.

Это **не завершение всего переноса**. Из 573 записей у трёх проверены конкретные
помощники, 121 содержит только инструкции для модели без доказанного end-to-end
сценария, 449 ещё требуют адаптера. Автоматический выбор скилла моделью отдельно
не подтверждён. План и границы: [RUNTIME-MIGRATION.md](RUNTIME-MIGRATION.md).

## Что внутри

- 344 рецепта скиллов, включая вложенные; 156 рецептов команд.
- 73 нативных профиля агентов с префиксом `pack-`; два других Markdown-файла в исходном каталоге агентов — справочные материалы.
- Один обнаруживаемый скилл `hamidun-pack`, который ищет по метаданным и читает полные инструкции только по необходимости.
- Единые правила исполнения для Codex: нативные инструменты, наследование моделей, безопасная работа с источниками, явные зависимости.
- 729 файлов исходного кода сохранены как **справочные `.source`, запрещённые к запуску контрактом пака**. Расширение — не техническая песочница; эти файлы не являются установленными адаптерами.
- 17 MCP-записей и два типа событий Claude hooks учтены в отчёте, но **не включены**.
- Проверяемый манифест SHA-256, карта происхождения и индивидуальный статус каждой записи.

Полная матрица: [bundle/COMPATIBILITY.md](bundle/COMPATIBILITY.md).
Машиночитаемый отчёт с пропусками и происхождением: [bundle/compatibility.json](bundle/compatibility.json).

### Как читать статусы

| Статус | Значение |
|---|---|
| `instructions-adapted` | Инструкции преобразованы; статическая проверка рецепта и его файловых зависимостей не нашла перечисленных runtime-зависимостей. Это **не** функциональный тест каждого сценария. |
| `requires-runtime-review` | Инструкции сохранены и снабжены Codex-контрактом, но есть ссылки на скрипты, Claude API, MCP, авторизацию или исходное окружение. Нужен нативный аналог либо отдельный проверенный адаптер. |

В текущей сборке 123 записи первого типа и 450 второго. Это статусы исторических рецептов;
поле `execution` отдельно описывает проверенные нативные замены. Статусы относятся ко всем скиллам,
командам и агентам вместе. Детектор консервативен: упоминание скрипта в примере тоже может
поставить запись во вторую группу. Никакая из 573 записей не помечена как прошедшая live-тест.

## Установка

Нужен Python 3.11+. Для **установки готовой сборки** сторонние Python-пакеты не нужны.

```powershell
# Windows — сначала посмотреть план
./install.ps1 -DryRun
./install.ps1

# Дополнительно установить роли (увеличит каталог агентов в контексте)
./install.ps1 -WithAgents
```

```bash
# macOS / Linux
sh install.sh --dry-run
sh install.sh
sh install.sh --with-agents
```

Установщик использует `CODEX_HOME`, если он задан, иначе `~/.codex`. Другую изолированную
директорию можно выбрать через `--target PATH` / `-Target PATH`.

Размещается только:

```text
<CODEX_HOME>/skills/hamidun-pack/SKILL.md
<CODEX_HOME>/packs/hamidun-pack/<source-commit>/...
<CODEX_HOME>/pack-manifests/hamidun-pack.json
<CODEX_HOME>/agents/pack-*.toml                 # только --with-agents
```

`config.toml`, существующий `AGENTS.md`, чужие скиллы и настройки Claude **не изменяются**.
Конфликт с изменённым/чужим файлом останавливает установку до копирования. Повторная установка
той же версии идемпотентна. Симлинки и junction в целевом пути запрещены; существующие hardlink
не перезаписываются на месте. Обновления управляемых файлов выполняются атомарной заменой.
Не устанавливайте одновременно с другим процессом, меняющим те же каталоги: это не защита от
злоумышленника, который целенаправленно подменяет пути между проверкой и записью.

Откройте новую задачу Codex и попросите: **«Используй hamidun-pack: найди рецепт документации API»**.
Если новый скилл не появился, перезапустите приложение. Установка не запускает ни одного агента.

## Параллелизм и расход контекста

При необходимости **осознанно объедините** [config.example.toml](config.example.toml) со своим конфигом:

```toml
[agents]
max_threads = 50
```

`max_threads` — совместимое старое имя `max_concurrent_threads_per_session`. Не задавайте оба.
Это потолок одновременно открытых субагентов без основного; не обязательный размер роя
и не отмена лимитов сервиса/подписки. Модели и reasoning наследуются из текущей среды.

По умолчанию в обнаружение попадает только **один** скилл-навигатор, а 573 рецептов остаются
вне стандартных skill roots. Полные тела и ссылки читаются по запросу. Даже метаданные имеют
цену в контексте; холодный каталог не означает, что загруженные инструкции бесплатны.
Общие правила пакета читаются навигатором, а не навязываются всем вашим задачам.

## Что НЕ переносится автоматически

- Личная память, история чатов, локальные базы, токены, OAuth-сессии и master credentials.
- Непроверенные значения моделей, Claude CLI env-переключатели и универсальные permissions.
- Фоновая инфраструктура, платные API, авторизация в сторонних сервисах и сетевые вызовы.
- Исполнение Claude hooks и предположение, что их payload совпадает с Codex hooks.
- Обещание, что Markdown-команда автоматически станет `/командой` в Codex.
- Бинарные/крупные ассеты и неподдерживаемые форматы: 265 исходных файлов явно перечислены
  в `compatibility.json` с причиной пропуска. Рецепт, использующий такой ассет, требует
  получения/проверки зависимости до выполнения.

Дополнительно исключены 2060 сырых экспортов n8n с данными примеров и 27 файлов двух скиллов (doc-coauthoring, building-an-exo), для которых upstream явно не установил лицензию. Они не потеряны в исходном публичном репозитории, но не распространяются этим паком.

В библиотеке сохранены исторические примеры. Контракт `ADAPTATION.md` ограничивает их
исполнение; старые имена инструментов не создают инструменты в текущем Codex. Для runtime-
зависимых сценариев сначала используйте доступный нативный инструмент или создайте и
проверьте отдельный адаптер. Не переименовывайте `.source` в исполняемые файлы вслепую.

## Удаление и откат

```powershell
./install.ps1 -Uninstall -DryRun
./install.ps1 -Uninstall
```

```bash
sh install.sh --uninstall --dry-run
sh install.sh --uninstall
```

Удаляются только файлы, которыми владеет установщик и чей hash не изменился. Пользовательские
правки и заранее существовавшие одинаковые файлы сохраняются. Пустые каталоги и журнал
оставляются намеренно. Рекурсивного удаления нет. Настройки возвращать не требуется:
установщик их не менял. Изменение лимита вручную откатывается отдельно.

## Воспроизводимая сборка и проверка

Источник берётся **только из публичного репозитория**, а не из домашнего каталога автора.
Готовые решения прежней персональной миграции перенесены как принципы и правила;
её приватные индексы, адаптеры с локальными привязками и данные не включены.

```bash
python -m pip install -r requirements-build.txt
git clone https://github.com/JHamidun/claude-code-config-pack.git work/upstream
git -C work/upstream checkout e9f5f9e019d3c6dc9fe83b00499f223b5f9e6d32
python scripts/build_pack.py --source work/upstream --output work/rebuilt-bundle
python scripts/validate_pack.py
python -m unittest discover -s tests -v
```

Сборщик принимает только закреплённую ревизию и чистые отслеживаемые исходники; вывод должен
идти в новую директорию вне source tree. Обновление upstream — отдельное изменение pin с
повторной проверкой. Не запускайте исходный Claude installer.

Проверка публикации ищет распространённые форматы секретов и личные пути; это ограниченный
статический сканер, а не доказательство отсутствия любых возможных секретов.

## Проверка зависимостей и приватности

Результаты и ограничения: [AUDIT.md](AUDIT.md). Полная карта файловых зависимостей: [bundle/dependency-audit.json](bundle/dependency-audit.json). Подробности исходных пропусков: [bundle/compatibility.json](bundle/compatibility.json).

Сборка не читает личный домашний конфиг, память, переписки или секреты. Локальная склейка скиллов автора не входит в этот репозиторий. Контакты и пути в справочных исходниках заменяются примерами; сырые workflow-экспорты не включаются. Авторство и публичные ссылки на upstream сохранены намеренно.

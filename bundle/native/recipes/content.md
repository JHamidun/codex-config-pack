# Native writing and editorial pipeline

Load the selected guide and only the references for this genre/platform. Preserve
its research, structure, voice, fact-check, proofread, editing and delivery stages,
but run them with native Codex tools rather than Claude commands or external-model
scripts. Sequential stages are valid; do not call them independent agent reviews.

Use the user's actual brief, supplied sources and current primary research. Keep
claims tied to sources, unknowns explicit, and quotations within permitted limits.
An example author's name, case, metrics, biography, channel or voice file is not the
current user's identity. Use only supplied/authorized writing samples. Missing
personal context must not be reconstructed from the pack author's private directories.
Workspace-local `.codex-context/author-profile.md` is optional and private by default.

For long works, keep a project-owned outline, glossary/canon, source map and per-part
draft/final files. Preserve the guide's continuity, contradiction and acceptance checks.
Do not mark unfinished chapters as FINAL or invent research to fill structural slots.

For covers and illustrations, use native image generation unless the user chose a
provider. Inspect references before editing. For DOCX/PDF/PPTX, use the installed
native document capability and its actual rendering/QA workflow; never return a renamed
text file as a binary artifact. Preserve the requested editable format and content.

Drafting is not publishing. Discover an authorized native connector only for an
explicit posting/sending request; verify destination/account, content, visibility
and actual readback. Do not use the author's account IDs, session paths or fixed recipients.
If a platform connection is absent, the completed draft remains deliverable, but
publishing remains blocked and must be described as such.

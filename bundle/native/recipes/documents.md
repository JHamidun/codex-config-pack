# Native document and visual artifact workflow

Discover the host's installed document, spreadsheet, PDF, presentation or design
capability that matches the requested output. Load that native skill, not a stale
provider wrapper. If the desktop exposes a bundled dependency locator, use it before
assuming Python/Node libraries are missing. CLI-only installations may need an explicit
project-local dependency setup; do not claim the desktop runtime exists everywhere.

Use the selected source guide for format-specific methodology, content structure,
styles, diagrams and validation requirements. Original `scripts/` commands are not
installed adapters: perform equivalent operations using the actual native capability
or a reviewed task-local implementation. Preserve source assets and editability.

Inspect actual inputs, fonts, images, slide/page counts and formats. Never invent
unprovided logos, portraits, QR contents, data tables or author identity. Keep user
assets/output in the workspace, never in the installed pack. Check file magic/MIME;
do not disguise HTML, JPEG or text with a different extension.

Produce the requested file, reopen/parse it, validate counts, formulas and links,
render when visual layout matters, and inspect representative pages plus any risky
overflow/cropping areas. A successful save is not visual QA. Preserve original inputs
and make destructive conversion/overwrite choices explicit.

For generic images use native generation/editing and inspect local references first.
For deterministic rendering, diagrams or format conversion use the matching native
document/browser renderer, not an image generator. Exact provider requests (Figma,
Gamma, Manus, etc.) require that provider's actual connected capability; native local
output is not evidence that an external provider operation ran.
